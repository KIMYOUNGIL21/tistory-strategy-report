**AI 음악 채널 운영일지 ③**

채널 3개 현황을 하루 열아홉 번 확인합니다. 제가 아니라 봇이요.

저는 코딩을 모르는 문과 직장인입니다. 그리고 순서를 틀린 사람이기도 합니다 — 자동화를 끝내기도 전에 채널부터 늘렸다가 초기 퀄리티가 무너졌습니다.

이 글에 코드는 한 줄도 안 붙입니다. 무엇을 자동화했는지보다, 자동화하면서 정한 **규칙**이 알맹이기 때문입니다.

### 1. 왜 만들었나 — 문제는 시간이 아니라 습관이었다

채널이 3개면 확인할 것도 3배입니다. 구독자, 어제 조회수, 새 댓글, 예약 영상이 제대로 걸렸는지.

한 번 여는 건 금방입니다. 문제는 그게 한 번으로 끝나는 일이 아니라 습관이 된다는 것이었습니다.

[입력] 자동화 전에 유튜브 스튜디오를 하루 몇 번쯤 열었나요? (대략도 괜찮습니다. "아침저녁 두 번"인지 "수시로"인지) — 답이 오면 이 자리에 실제 장면 한 줄을 넣습니다. 확인 전까지는 비워둡니다.

그래서 기준을 하나 바꿨습니다. **봐야 아는 것을, 생기면 알려주는 것으로.**

### 2. 무엇이 언제 오나 — 표 하나로

전부 텔레그램 봇 하나로 옵니다. 제 PC는 꺼져 있어도 됩니다. 코드는 클라우드(GitHub Actions)에서 알아서 돌고, 제 노트북은 코드를 고칠 때만 씁니다.

| 시각(KST) | 오는 것 | 내가 하는 일 |
|---|---|---|
| 매일 08:30 | 예약(공개 예정) 영상 현황 — 채널별 공개 시각순 | 예약 구멍 확인 |
| 매일 08:30 | 예약 롱폼 제목 검수 — 문제 있을 때만, 수정안 2개 + [적용] 버튼 | 버튼 누르거나 무시 |
| 매일 09:00 | 일일 리포트 — 구독자·조회수 증감, 새 영상, 최근 인기 | 읽기만 |
| 08:30~23:30 매시 30분 | 감시 — 새 댓글(답글 초안 + [게시] 버튼)·급상승·마일스톤·24시간 성적표·경쟁 채널 새 영상 | 변화 있을 때만 옴 |
| 월요일 09:10 | 주간 — 시청시간·평균 지속·구독 순증·유입 경로·주간 1위 + 벤치마크 채널 | 읽기만 |
| 매월 1일 09:20 | 월간 — 요일별 시청 분포, 연령·성별·기기 | 업로드 요일 조정 |
| 매월 2일 07:00 | 제목 성공방정식 갱신 | 없음 (다음 달 검수 기준이 바뀜) |
| 아무 때나 | `/현황` — 3채널 즉시 조회 | 궁금할 때 |

표에서 제일 중요한 줄은 4번째입니다. **변화가 없으면 아무것도 오지 않습니다.** 구독자가 그대로고 댓글도 없으면, 그 시각엔 텔레그램이 조용합니다.

조용한 게 정상이라는 걸 아는 것. 그게 스튜디오를 안 열게 된 진짜 이유입니다.

[입력] 위 캡처 필요 — 일일 리포트 메시지 1장, 제목 검수 카드(버튼 보이게) 1장. 채널명은 나와도 되지만 채널 ID·토큰이 찍힌 화면은 제외

### 3. 규칙 하나 — 제목은 절대 자동으로 바꾸지 않는다

이게 이 시스템의 제1원칙입니다.

AI가 제목을 검수는 합니다. 하지만 고치지는 못합니다. 텔레그램 카드에 뜬 [적용] 버튼을 제가 눌러야만 유튜브에 반영됩니다.

이유는 한 문장입니다. **제목은 마케팅 자산이기 때문입니다.** 자산을 자동으로 건드리게 두면, 잘 되던 것이 왜 안 되는지 나중에 알 수가 없습니다.

검수 카드는 이런 형식으로 옵니다. (형식만 보여드립니다)

> ✏️ 제목 검수: (채널명)
> 📅 (요일) (시각) 공개 예정
> 현재(nn점): "(원래 제목)"
> 문제: (지적 2~3개)
>
> 1안(nn점) (수정안)
> 2안(nn점) (수정안)
> [✅ 1안 적용] [✅ 2안 적용] [🚫 무시]

검수 대상은 롱폼(3분 초과)뿐입니다. 숏폼은 아예 안 봅니다. 숏폼 제목까지 검수하면 알림이 하루에 몇 개가 될지 몰라서 제가 대상에서 뺐습니다.

### 4. 규칙 둘 — 확신 없으면 통과

AI에게 검수를 시켜보면 바로 알게 되는 게 있습니다. **뭐라도 지적하려고 든다는 것.**

지적이 많아지면 알림을 안 읽게 됩니다. 안 읽는 알림은 없는 알림입니다.

그래서 통과 쪽으로 두 겹을 걸었습니다.

- 심사관 역할에 "확신이 없으면 통과"를 명시 — 명백한 결함이 있을 때만 불합격
- 개선안이 나오면 원제와 개선안을 **같은 기준으로 다시 블라인드 채점** → 개선안이 원제보다 10점 이상 높을 때만 알림

10점을 못 넘기면 조용히 넘어갑니다. 그날 검수한 게 전부 통과면 이 한 줄만 옵니다. "✅ 롱폼 제목 검수: 3건 모두 통과".

금지 규칙도 넣었습니다. "충격", "경악", "발칵" 같은 허위 낚시 표현은 제안하지 않습니다. 이런 문법을 쓰는 채널은 성과가 좋아도 벤치마크에서 뺐습니다.

하나 더. 같은 곡을 제목만 바꿔 여러 번 올리는 건 저의 의도된 전략입니다. 그래서 "비슷한 제목이 있다"는 지적은 못 하게 막았고, 완전히 똑같은 제목일 때만 중복으로 봅니다.

### 5. 규칙 셋 — 알림을 한 메시지에 몰지 않는다

처음엔 예약 영상 현황을 일일 리포트에 같이 넣었습니다. 메시지가 길어지니까 안 읽더군요. 그래서 08:30과 09:00으로 뗐습니다.

댓글 알림도 마찬가지입니다. 댓글 하나에 메시지 하나씩 갑니다. [게시] 버튼이 그 댓글에 붙어 있어야 하니까요. 대신 채널당 한 번에 5개까지만.

**긴 메시지는 정보가 아니라 소음입니다.** 새 기능을 붙일 때도 메시지가 길어질 것 같으면 무조건 별도 전송으로 뺍니다.

### 6. 남의 채널을 자로 쓰는 법 — 히트는 "3배 & 5,000회"

제 감으로는 좋은 제목을 알 수 없습니다. 그래서 벤치마크 채널의 제목을 자로 씁니다.

문제는 구독자 수가 다른 채널을 어떻게 비교하느냐입니다. 남의 채널 클릭률(CTR)은 볼 수가 없습니다. 그래서 조회수 배수를 대리 지표로 씁니다.

- **히트** = 그 채널 롱폼 조회수 **중앙값의 3배 이상 & 5,000회 이상**
- **실패** = 그 채널 중앙값의 0.7배 이하

5,000회 하한을 같이 둔 이유는 단순합니다. 원래 조회수가 적은 영상이 우연히 3배가 된 걸 히트로 착각하면, 그 다음 달 제 제목이 통째로 그쪽으로 끌려갑니다.

매월 2일, 이 히트 제목과 실패 제목을 대조해서 채널별 규칙서를 다시 뽑습니다. 그 규칙서가 다음 한 달간 제목 검수의 기준이 됩니다.

지금 규칙서는 채널당 2,100~2,500자쯤 됩니다. **3개 채널이 각각 다른 규칙서를 갖고 있습니다.** 트로트TV의 히트 문법과 그밤라디오의 히트 문법은 같지 않으니까요.

### 7. 자동화보다 먼저 정해야 했던 것 — 제가 틀린 순서

여기서 고백을 하나 해야겠습니다.

저는 자동화가 완성되기 전에 채널을 늘렸습니다. 결과는 초기 퀄리티 붕괴였고, 그걸 되돌리는 데 한참 애를 먹었습니다. 제가 그랬습니다.

교훈은 이겁니다. **자동화는 굴러가는 걸 빠르게 해줄 뿐, 안 굴러가는 걸 굴러가게 해주지 않습니다.**

채널을 어쩌다 3개까지 늘리게 됐는지, 그때 뭐가 무너졌는지는 [지난 운영일지에]([확인] 3번 글 URL) 숫자까지 적어뒀습니다.

### 8. 돈은 얼마나 드나

[확인] 아래 한도는 2026년 7월 기준입니다. 각 서비스 요금제는 바뀝니다.

| 쓰는 것 | 역할 | 비용 |
|---|---|---|
| GitHub Actions | 정해진 시각에 코드 실행 | 프리 플랜, 비공개 저장소 월 2,000분 포함 (공개 저장소는 무료) |
| 텔레그램 봇 | 알림 받기 | 기본 메시지 무료 |
| YouTube Data API | 채널·영상 조회 | 무료, 하루 10,000 유닛 |
| Cloudflare Workers | 버튼·`/현황` 처리 | 무료 하루 100,000 요청 |
| OpenAI API | 답글 초안·제목 검수 | 유료 (사용량 과금) |

[입력] 이 시스템 때문에 실제로 나가는 월 비용(주로 OpenAI API)이 얼마인가요? 대략의 금액이라도 있으면 표에 채웁니다. 없으면 "유료"로만 두겠습니다.

주의할 점 하나. GitHub 공식 문서는 **예약 실행이 고부하 시 지연될 수 있고, 심하면 큐에 있던 작업이 드롭될 수도 있다**고 명시하고 있습니다. 문서는 정각(매시 0분)이 특히 붐빈다며 시각을 분산하라고 권합니다.

즉 09:00은 약속이 아니라 희망입니다. 리포트가 몇 분 늦게 와도 고장 난 게 아닙니다.

### 자주 나오는 질문

**Q. 코딩을 모르는데 이런 게 되나?**
제 저장소 맨 앞에는 코드가 아니라 지시서가 있습니다. 첫 줄이 이렇습니다. "운영자는 비개발자입니다. 설명은 쉽게, 전문용어는 풀어서 써주세요." 이 시스템은 그 문장 위에 지어졌습니다.

**Q. 채널이 1개여도 필요한가?**
1개면 스튜디오로 충분할 수 있습니다. 확인이 곱셈이 되기 시작하는 건 2~3개부터입니다.

**Q. 켜자마자 알림이 오나?**
안 옵니다. 첫 실행은 알림 없이 현재 상태만 기록합니다. 비교할 어제가 없으면 그건 알림이 아니라 소음이니까요. 업로드 24시간 성적표도 비교 데이터가 3개 쌓이기 전엔 "평소의 몇 배"를 말하지 않고 "수집 중"이라고만 합니다.

### 마무리 — 다음 질문은 "그래서 뭘 바꾸나"

24시간 성적표가 "평소의 40%, 제목·썸네일 점검 고려"라고 말하는 날이 있습니다.

알림은 여기까지입니다. 뭘 알려주는 것과 뭘 바꿔야 하는지는 다른 문제입니다.

### 오늘 글 다섯 줄 요약

1. 확인은 3분짜리 일이 아니라 습관이 됩니다. "봐야 아는 것"을 "생기면 알려주는 것"으로 바꾸세요.
2. 제목은 절대 자동으로 바꾸지 마세요. 검수는 AI가, 결정은 버튼으로. 제목은 마케팅 자산입니다.
3. 검수 원칙은 "확신 없으면 통과". 원제보다 확실히 나을 때만 제안하게 하세요. 잔소리가 되는 순간 알림은 죽습니다.
4. 알림은 변화가 있을 때만, 그리고 한 메시지에 몰지 마세요. 긴 메시지는 안 읽힙니다.
5. 자동화가 굴러가기 전에 채널을 늘리지 마세요. 제가 그 순서를 틀렸습니다.
